# verify — проверка без живых чатов

Бот банит живых людей, поэтому проверять его на настоящих чатах нельзя. Вместо этого:

```bash
npm run verify        # typecheck + все тесты (включая сухой прогон webhook)
npm run verify:e2e    # только сухой прогон webhook, быстро
```

## Что такое сухой прогон

`tests/e2e/webhook.test.ts` шлёт апдейты Telegram в настоящий `api/telegram.ts`
(с секретом webhook), бот обрабатывает их целиком, как в проде. Подменено всё внешнее
(`tests/e2e/sandbox.ts`, `tests/e2e/harness.ts`):

- env — фиктивный; настоящий `.env` не читается;
- `fetch` — отвечает только поддельный Upstash в памяти, любой другой хост → ошибка;
- все вызовы Telegram API перехватываются и записываются (`tgCalls`), наружу ничего не уходит;
- `getChatMember` отвечает из таблицы `setMember(chatId, userId, status | {error})`.

При падении в сообщении — трейс вызовов Telegram по шагам (метод, чат, пользователь, текст).

## Как добавить сценарий

1. В `tests/e2e/webhook.test.ts` новый `test(...)`: `setMember(...)`, затем
   `await deliver({ message_reaction | message | chat_member | callback_query ... })`.
2. Проверять по `writes(r.calls)` (вызовы, кроме `get*`) и `DESTRUCTIVE` (удаления).
3. Новые id пользователей — уникальные в файле (состояние Redis общее на весь прогон).
4. Если бот вызвал команду Redis, которой нет в фейке, тест упадёт с
   `fake Redis: <КОМАНДА>`. Добавить её в `runCommand` в `sandbox.ts`.

## Правила

- Красный тест не обходить: не ставить skip, не добавлять sleep/повторы. Найти причину;
  если тест сам неверен — исправить его и написать в PR, почему.
- После трёх неудачных попыток починить — остановиться и описать владельцу, что не так.
- Хук Stop (`.claude/settings.json` → `tools/verify/stop-hook.mjs`) сам запускает
  `npm run verify`, если в `src/`, `api/`, `tests/` есть незакоммиченные изменения.
